## 压测与 E2E 中发现并修复的问题

1. 业务 ID 4 字节 hex 在万级批量插入时碰撞 → 升级 8 字节（64 位熵）；
2. BackgroundTasks 晚于依赖清理提交的时序问题 → 上传后显式提交任务行；
3. 前端 api client 缺失 Content-Type 导致登录 500 → 显式声明 application/json；
4. 复习作答页守卫误判 generating 态 → 仅在无会话时弹回；
5. toast 插件在浏览器 ESM 下使用 require → 改顶层导入；
6. 看板聚合缓存跨测试泄漏 → 测试隔离 + TTL 失效入口。

## 演示与部署

- 一键启动：`powershell -File scripts/start.ps1` 或 `bash scripts/start.sh` 或 `docker compose up`
- 首次进入自动揭示本地 Token；数据全部在 data/ 目录
- 接入真实 AI：设置页配置 DeepSeek Key，`RECALL_AI_MOCK=false` 重启
- 接入真实 OCR：部署 PaddleX 服务后 `RECALL_OCR_MOCK=false`（ocr/client.py）
- 压测演示数据：data/ 现有 10000+ 条错题，删除 data/recall.sqlite3 可回到空库（自动重建与种子）
